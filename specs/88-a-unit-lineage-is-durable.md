# 88 - A unit's lineage is durable: conflicts merge, fresh runs adopt, escalations resume, plan amendments land

**Goal:** four loop behaviours discard or strand reviewed work, each seen on the spec-86 run
(2026-09-09/10). (1) An integration merge conflict re-parks the implementer with "re-implement
off the current run-branch tree", the worktree is rebuilt from the run-branch tip, and the
unit's approved rounds are gone: u86-c3 lost rounds 1-3 to a conflict in generated audit files
alone and was then rejected for a defect its abandoned lineage had already fixed
(adj-u86c3-r4-out-of-line-exclusion-still-unmigrated). (2) A fresh run adopts a prior unit's
durable branch only when the planner reproduces the same slug; the planner named criterion 1
`u86-c1-exclusion` where the escalated run had `u86c1-tests-not-nodes`, so `Worktree::create`
(src/worktree.rs:131) would have branched from base and dropped six reviewed rounds; the operator
pre-created the branch by hand. (3) `UnitEscalated` is final for a run and the reaper removes the
worktree, so a human who wants one more attempt must replan the whole spec. (4) The plan and
plan-critique stages integrate nothing (`REVIEW_ONLY_NO_ARTIFACT`, src/conductor.rs:641); the
first run's planner committed an approved spec amendment (b6a471c) in its worktree, it reached no
branch, and the fresh run's critique rejected the plan for the gap that amendment had closed.
Operator rule: a unit's reviewed history is never discarded by the harness.

## Design

INTEGRATE-CONFLICT MERGES, decided: when integration hits a merge conflict, the conductor merges
the run branch INTO the unit worktree (`git merge --no-commit <run-branch>`, conflict markers
left in place, the unit branch untouched), re-parks the implementer with a remediation that
lists ONLY the conflicting paths, and charges NO remediation attempt: a conflict is not a defect
of the unit. The implementer resolves and commits on the SAME branch; every prior commit stays.
A conflict confined to regenerable artifacts (paths a `regenerate:` list in workflow.yml names -
here `docs/audit/*.json` - the report beside them is partly hand-written and its generator rewrites only one section, so a conflict in it is source, never regenerable) is resolved by the conductor itself by running the named regeneration
command in the worktree and committing, with no spawn at all.

ADOPTION KEYS ON THE CRITERION, decided: a unit adopts a prior run's `rigger/u/<id>` branch when
the prior unit's `criterion_stable_id` (src/conductor.rs:8676) equals this unit's, regardless of
the planner's slug: the conductor creates `rigger/u/<new-id>` at the prior tip (a new ref, never
a rename, so the old name stays valid), `Worktree::create` then adopts as today, and `UnitStarted`
records `adopted_from: {unit, tip}`. Prior units that reached `UnitIntegrated` are never adopted
(their work is on the base already).

ESCALATION RESUMES, decided: `rigger resume-unit <unit> [--attempts N]` (default 1) appends
`UnitResumed { unit, attempts_granted, by: "operator" }` to the run stream - one new event type,
named here deliberately - and the next `rigger step` re-parks the implementer on the durable
branch with the escalation's final adjudication as its remediation and the granted attempts as
its new bound; a second escalation after the grant is final again until the next resume.
`rigger status` shows "resumed by operator (N attempt(s) granted)" on the unit; the driver's
escalated-fixpoint stop names the command.

PLAN AMENDMENTS LAND, decided: a plan or plan-critique stage may commit ONLY under `specs/`;
at the stage's integration point the conductor cherry-picks those commits onto the run branch
(so the next critique worktree, branched from the run branch, sees them) and records the shas
on `UnitIntegrated` in place of the review-only marker; a plan-stage commit touching any other
path fails the stage loudly with the offending paths.

CONSTRAINTS WALK: conflict in both a source file and a regenerable artifact - the artifact is
regenerated by the conductor after the implementer resolves the source conflict, in that order.
Adoption when two prior units share the criterion (a replanned run) - the most recent
non-integrated tip wins and the choice is recorded. Resume on a unit whose durable branch is
gone - refused with the branch name and the reflog hint. A plan amendment that conflicts with a
concurrent operator commit under `specs/` - the cherry-pick fails loudly and the stage escalates
the conflict to a human instead of dropping the amendment. Crash-resume mid-merge - the merge is
worktree state, not log state: the re-park is idempotent (a re-run `git merge` on a tree already
carrying markers is refused, and the step reads the recorded conflict list instead).

## Global constraints

- Hyphens, never em dashes. Both feature lanes green (fmt, clippy -D warnings, test, default
  and --no-default-features); no-os-kill and reap audits green.
- One new event type (`UnitResumed`); no new dependency.
- The operator's installed rigger binary is never replaced or modified by any unit.

## Done when

- [ ] a test proves AN INTEGRATE-CONFLICT MERGES INTO THE UNIT: a unit whose integration
  conflicts is re-parked with the run branch merged into its worktree, its branch keeps every
  prior commit, no attempt is charged, and a conflict confined to a registered regenerable path
  is resolved by regeneration with no spawn. This criterion OWNS conflict handling; adoption is
  criterion 2's, NOT this one's.
- [ ] a test proves ADOPTION KEYS ON THE CRITERION: a fresh run whose planner proposes a new
  slug for a criterion a prior run left un-integrated starts that unit at the prior tip with
  `adopted_from` recorded, and never adopts an integrated unit. This criterion OWNS adoption;
  resume is criterion 3's, NOT this one's.
- [ ] a test proves AN ESCALATION RESUMES: `rigger resume-unit` on an escalated unit re-parks
  its implementer on the durable branch with the granted attempts, `rigger status` names the
  grant, and a run at an escalated fixpoint names the command in its stop reason. This criterion
  OWNS `UnitResumed` and the command; conflicts and adoption are criteria 1 and 2's, NOT this
  one's.
- [ ] a test proves PLAN AMENDMENTS LAND: a plan-stage commit under `specs/` reaches the run
  branch before the next critique worktree is created, and a plan-stage commit elsewhere fails
  the stage naming the path. This criterion OWNS plan-stage integration and introduces no unit
  lifecycle change.
- [ ] both feature lanes green (fmt, clippy, test on default and --no-default-features).
